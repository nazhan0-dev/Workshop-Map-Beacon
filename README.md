# Beacon — ระบบจัดเวร รปภ.

ระบบจัดเวรเจ้าหน้าที่รักษาความปลอดภัยบนแผนที่ ผู้ดูแลลากคนลงจุดเวรตามวันและกะ ส่วน รปภ. ดูเวรของตัวเอง กดเข้ากะด้วย GPS รายงานเหตุการณ์ และแจ้งลาได้จากมือถือ

ใช้ได้ทั้งบนคอมและมือถือ (responsive)

## ทำอะไรได้บ้าง

### ผู้ดูแล (Admin)
- **จัดเวรบนแผนที่:** เลือกวันและกะ แล้วลากชื่อพนักงานลงหมุด หมุดเปลี่ยนสีตามสถานะ ครบ / ขาด / ว่าง
- **กันจัดผิด:** จุดเต็ม, คนเดียวอยู่สองจุดในกะเดียว, เวรต่อกันหลายกะ (ถามยืนยัน), คนที่ลาอนุมัติแล้ว
- **คัดลอกเวร:** ทั้งวัน หรือทั้งสัปดาห์ ข้ามคนที่ซ้ำ จุดที่เต็ม และคนที่ลา
- **ภาพรวมประจำวัน:** คนเข้าเวรแต่ละกะ, จุดที่ขาดคน, การเข้ากะ (ตรงเวลา / สาย / ยังไม่มา), เหตุการณ์, คนลาวันนี้
- **จัดการพนักงาน:** เพิ่ม แก้ ลบ, รีเซ็ตรหัสผ่าน, ตั้งตำแหน่ง หัวหน้า / รองหัวหน้า / เจ้าหน้าที่
- **จัดการจุดเวร:** พิกัดบนแผนที่, จำนวนคนต่อกะ, หน้าที่, ข้อควรระวัง, เบอร์ติดต่อ, ระยะที่กดเข้ากะได้
- **รายงานเหตุการณ์:** ดู กรอง รับเรื่อง ปิดเรื่องพร้อมสรุปผล
- **การลา:** อนุมัติ / ไม่อนุมัติ แล้วให้ระบบแนะนำคนแทน

### รปภ. (User)
- เวรวันนี้พร้อมนับถอยหลัง, เวรถัดไป, ปฏิทินเวร, เพื่อนร่วมกะพร้อมปุ่มโทร
- **เข้ากะ / ออกกะ** ด้วย GPS ต้องอยู่ในระยะของจุดเวร แนบรูปหน้างานได้
- นำทางไปจุดเวรในแอป
- **รายงานเหตุการณ์** 3 ระดับ (ปกติ / ผิดปกติ / ด่วน) แนบรูปได้ ถ้าเลือกด่วนจะขึ้นปุ่มโทรหาหัวหน้า
- **แจ้งลา** ลาป่วย / ลากิจ / ลาพักร้อน ถ้าลาป่วยวันนี้ ระบบถอนออกจากเวรทันที
- เปลี่ยนรหัสผ่าน, ออกจากระบบทุกอุปกรณ์

### หัวหน้า / รองหัวหน้า
- เห็นว่าใครในกะเข้ากะแล้ว ใครยังไม่มา
- รับเรื่องและปิดเรื่องที่ทีมรายงานในกะของตัวเองได้

## ความปลอดภัย

- token เก็บใน **cookie แบบ httpOnly** (SameSite=Lax, Path=/api, Secure เมื่อใช้งานจริง) JavaScript ในหน้าเว็บอ่านไม่ได้
- **ยกเลิก token ได้ทันที:** เปลี่ยนรหัส, admin รีเซ็ตรหัส, ออกจากระบบทุกอุปกรณ์, ลบบัญชี หรือเปลี่ยนสิทธิ์ ทุกกรณีมีผลกับคำขอถัดไปเลย (เช็กกับฐานข้อมูลทุกครั้ง)
- **กันยิงคำขอข้ามเว็บ (CSRF):** ตรวจ Origin/Referer ของคำขอที่แก้ข้อมูล และ CORS อนุญาตเฉพาะหน้าเว็บของระบบ
- **กันเดารหัสผ่าน:** ผิด 5 ครั้งพัก 15 นาที และเวลาตอบเท่ากันไม่ว่าชื่อผู้ใช้จะมีอยู่จริงหรือไม่
- ใช้ placeholder กับ SQL ทุกคำสั่ง (กัน SQL injection), ตรวจความยาวและรูปแบบข้อมูลทุกช่อง
- ใช้ทรานแซกชันพร้อมล็อกแถว กันจัดเวรพร้อมกันจนเกินจำนวนคน
- ส่ง security header ทุกคำตอบ (nosniff, X-Frame-Options, CSP, no-store) และไม่บอกว่าใช้ Express
- production ไม่ยอมเปิดถ้า `JWT_SECRET` สั้นหรือยังเป็นค่าตัวอย่าง

## ข้อมูลที่เก็บ

ฐานข้อมูล MySQL มี 5 ตาราง

| ตาราง | เก็บอะไร | ข้อมูลส่วนบุคคล |
|---|---|---|
| `users` ผู้ใช้ | ชื่อ-นามสกุล, ชื่อผู้ใช้, รหัสผ่าน (เข้ารหัสด้วย bcrypt), สิทธิ์ (ADMIN / USER), ตำแหน่ง (หัวหน้า / รองหัวหน้า / เจ้าหน้าที่), หน้าที่, เบอร์โทร, เลขรุ่นของ token (ใช้ยกเลิกการล็อกอิน) | ชื่อ, เบอร์โทร |
| `locations` จุดเวร | ชื่อจุด, พิกัด, จำนวนคนต่อกะ, หน้าที่, ข้อควรระวัง, เบอร์ติดต่อจุด, ระยะที่กดเข้ากะได้ | – |
| `assignments` เวร | ใคร อยู่จุดไหน วันไหน กะไหน, เวลารับทราบ, **เวลาเข้ากะ/ออกกะ**, **พิกัดและระยะจากจุดตอนกดเข้ากะ**, **รูปหน้างาน** (ถ้าแนบ) | พิกัด GPS, รูป |
| `incidents` รายงานเหตุการณ์ | ผู้รายงาน, จุด วัน กะ, ระดับ, รายละเอียด, **รูป** (ถ้าแนบ), สถานะ, ผู้รับเรื่อง/ปิดเรื่อง, สรุปผล | รูป |
| `leaves` การลา | ผู้ลา, ประเภท, ช่วงวันและกะ, เหตุผล, **รูปเอกสาร เช่น ใบรับรองแพทย์** (ถ้าแนบ), สถานะ, ผู้อนุมัติ, เวรที่ถูกถอนออก | เหตุผลการลา, ใบรับรองแพทย์ |

นอกจากนี้มีตาราง `schema_migrations` ซึ่งบันทึกว่ารันไฟล์อัปเดตฐานข้อมูลไปแล้วกี่ไฟล์ ไม่มีข้อมูลผู้ใช้

**สิ่งที่ระบบไม่เก็บ**
- **ไม่ติดตามตำแหน่งตลอดเวลา:** server ของระบบได้พิกัดเฉพาะตอนกดเข้ากะครั้งเดียว ส่วนตำแหน่งระหว่างนำทางไม่ถูกส่งมาเก็บ
- **ไม่เก็บรหัสผ่านตัวจริง:** เก็บเฉพาะค่าที่เข้ารหัสแล้ว (bcrypt) ซึ่งถอดกลับไม่ได้
- **ไม่เก็บ token ในฐานข้อมูล:** token อยู่ใน cookie ของเบราว์เซอร์ ส่วนฐานข้อมูลเก็บแค่เลขรุ่นไว้ยกเลิก
- ไม่เก็บ IP หรือประวัติการเข้าเว็บ (ตัวนับการเดารหัสผ่านอยู่ในหน่วยความจำ และหายไปเมื่อปิด server)

**ใครเห็นอะไร**
- **รปภ.:** เห็นเวรของตัวเอง ชื่อและเบอร์ของเพื่อนร่วมกะ รายงานและการลาของตัวเอง
- **หัวหน้า / รองหัวหน้า:** เห็นเพิ่ม คือสถานะเข้ากะและรายงานของทีม เฉพาะกะที่ตัวเองเข้าเวร
- **ผู้ดูแล:** เห็นทุกอย่าง รวมพิกัดและรูปตอนเข้ากะ

**บริการภายนอกที่หน้าเว็บเรียกใช้** (ไม่ผ่าน server ของระบบ)
- **OpenStreetMap:** โหลดภาพแผนที่ บริการจะเห็นว่ากำลังดูบริเวณไหน
- **OSRM** (`router.project-osrm.org`): ตอนกดนำทางในแอป ระบบส่ง **ตำแหน่งปัจจุบันและปลายทาง** ไปเพื่อคำนวณเส้นทาง
- **Google Maps / Waze / Apple Maps:** ส่งเฉพาะพิกัดจุดเวร ตอนผู้ใช้กดปุ่มเปิดแอปเอง

**ลบข้อมูล:** ลบพนักงานแล้ว เวร รายงาน และการลาของคนนั้นถูกลบตามไปด้วย ลบจุดเวรแล้ว เวรและรายงานของจุดนั้นก็ถูกลบตามไปด้วย

> ข้อมูลข้างต้นมีข้อมูลส่วนบุคคล (ชื่อ, เบอร์, พิกัด, รูป, ใบรับรองแพทย์) ถ้าใช้งานจริงในองค์กร ควรแจ้งพนักงานว่าเก็บอะไรและเพื่ออะไร ตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล (PDPA) และกำหนดว่าจะเก็บไว้นานเท่าไร

## วิธีรัน

ต้องมี **Node.js 20.19+** และ **MySQL** ที่รันอยู่

### 1. API

```bash
cd server
npm install
cp .env.example .env     # แล้วแก้ DB_PASSWORD และ JWT_SECRET
npm run db:init          # สร้างฐานข้อมูล + ข้อมูลตัวอย่าง (ครั้งแรกครั้งเดียว)
npm run dev              # http://localhost:5000
```

ถ้าไม่สะดวกใช้ terminal ให้เปิดไฟล์ `server/sql/setup-workbench.sql` ใน MySQL Workbench แล้วกดปุ่มสายฟ้า

### 2. หน้าเว็บ (อีก terminal)

```bash
cd client
npm install
npm run dev              # http://localhost:5173
```

### อัปเดตฐานข้อมูลเดิมหลังดึงโค้ดใหม่

```bash
cd server
npm run db:migrate
```

รันซ้ำได้ ไฟล์ใน `sql/migrations` ที่รันไปแล้วจะข้าม

### บัญชีตัวอย่าง

| สิทธิ์ | ชื่อ | ชื่อผู้ใช้ | รหัสผ่าน |
|---|---|---|---|
| ผู้ดูแล | ผู้ดูแลระบบ | `admin@beacon.com` | `admin1234` |
| หัวหน้า | นัส, นิส | `nas@beacon.com`, `nis@beacon.com` | `123456` |
| รองหัวหน้า | นิฟ, ริส | `nif@beacon.com`, `ris@beacon.com` | `123456` |
| เจ้าหน้าที่ | อา, ยานี, นัสรีน | `ar@beacon.com`, `yanee@beacon.com`, `nasreen@beacon.com` | `123456` |

ชื่อผู้ใช้ไม่สนตัวพิมพ์เล็กใหญ่ พิมพ์ `admin@Beacon.com` ก็เข้าได้

### ทดสอบบนคอมหรือมือถือในวงแลน

- คอมส่วนใหญ่ไม่มี GPS และมือถือที่เปิดเว็บแบบ `http://192.168.x.x` จะไม่ให้อ่านตำแหน่ง ตั้ง `CHECKIN_GPS=off` ใน `server/.env` เพื่อข้ามการเช็กระยะตอนทดสอบ
- เปิดจากมือถือ: ใส่ `CLIENT_URL=http://localhost:5173,http://<IP เครื่อง>:5173` ใน `server/.env` และ `VITE_API_URL=http://<IP เครื่อง>:5000/api` ใน `client/.env`

## API

ยืนยันตัวตนด้วย cookie `beacon_token` ที่ได้จาก `POST /api/auth/login` (เครื่องมืออื่นส่ง `Authorization: Bearer <token>` แทนได้)

| สิทธิ์ | Method | Path | หน้าที่ |
|---|---|---|---|
| ทุกคน | GET | `/api/health` | API และฐานข้อมูลพร้อมไหม |
| ทุกคน | POST | `/api/auth/login` | เข้าสู่ระบบ (ตั้ง cookie) |
| ทุกคน | POST | `/api/auth/logout` | ออกจากระบบเครื่องนี้ |
| ล็อกอิน | POST | `/api/auth/logout-all` | ออกจากระบบทุกอุปกรณ์ |
| ล็อกอิน | GET | `/api/auth/me` | ข้อมูลของฉัน |
| ล็อกอิน | PUT | `/api/auth/password` | เปลี่ยนรหัสผ่าน |
| ล็อกอิน | GET | `/api/locations` | รายการจุดเวร |
| Admin | POST · PUT · DELETE | `/api/locations/:id` | เพิ่ม แก้ ลบจุด |
| Admin | GET · POST · PUT · DELETE | `/api/users/:id` | จัดการพนักงาน |
| Admin | POST | `/api/users/:id/reset-password` | รีเซ็ตรหัสผ่าน |
| Admin | GET | `/api/assignments?date=&shift=` | เวรของวัน/กะ พร้อมสถานะเข้ากะ |
| Admin | POST | `/api/assignments` | จัดคนเข้าจุด |
| Admin | PATCH · DELETE | `/api/assignments/:id` | ย้ายจุด / ถอนออก |
| Admin | GET | `/api/assignments/:id/check-in-photo` | รูปตอนเข้ากะ |
| Admin | POST | `/api/assignments/copy` | คัดลอกเวร `{ mode: "day" \| "week", from, to }` |
| Admin | GET | `/api/dashboard?date=` | ภาพรวมประจำวัน |
| Admin | GET | `/api/incidents` · `/summary` · `/:id` | รายงานเหตุการณ์ |
| Admin | PATCH | `/api/incidents/:id` | รับเรื่อง / ปิดเรื่อง |
| Admin | GET | `/api/leaves` · `/summary` · `/on` · `/suggest` · `/:id` | การลา และคนแนะนำมาแทน |
| Admin | PATCH | `/api/leaves/:id` | อนุมัติ / ไม่อนุมัติ |

  src/middlewares/      ยืนยันตัวตน, ความปลอดภัย, จัดการ error
  src/utils/            กติกาธุรกิจ: กะ, การเข้ากะ, การลา, รายงาน, ตรวจข้อมูล

## ขึ้นใช้งานจริง

1. ตั้ง `NODE_ENV=production`, `JWT_SECRET` แบบสุ่มยาว 32+ ตัว, `CLIENT_URL` เป็นโดเมนจริง
2. ต้องใช้ **HTTPS** ทั้งหน้าเว็บและ API: cookie แบบ Secure และ GPS ในมือถือใช้ได้เฉพาะ https
3. หน้าเว็บกับ API ควรอยู่โดเมนเดียวกันหรือโดเมนย่อยเดียวกัน เช่น `app.example.com` กับ `api.example.com` เพื่อให้ cookie แบบ SameSite=Lax ใช้ได้
4. อยู่หลัง reverse proxy ให้ตั้ง `TRUST_PROXY=true`
5. `cd client && npm run build` แล้วนำโฟลเดอร์ `dist/` ขึ้นเว็บ

## ข้อจำกัดที่รู้อยู่

- ตัวนับการเดารหัสผ่านอยู่ในหน่วยความจำ ใช้ได้กับ server ตัวเดียว (หลายตัวต้องย้ายไป Redis)
- รูปแนบเก็บในฐานข้อมูลแบบ base64 (ย่อขนาดแล้ว) ถ้าใช้งานหนักควรย้ายไปที่เก็บไฟล์ เช่น S3
- หน้าเว็บอัปเดตด้วยการดึงข้อมูลทุก 30–60 วินาที ยังไม่มีแจ้งเตือนแบบ push
- GPS ปลอมได้ด้วยแอปปลอมตำแหน่ง รูปหน้างานช่วยตรวจสอบได้บางส่วน
- ตอนนี้นำทางผ่าน OSRM เซิร์ฟเวอร์สาธิต ซึ่งไม่ได้ทำไว้สำหรับใช้งานจริง ขึ้นระบบจริงควรตั้ง OSRM เองหรือใช้บริการแบบเสียเงิน
- ยังไม่มีการลบข้อมูลเก่าอัตโนมัติ เช่น รูปและพิกัดตอนเข้ากะ ควรกำหนดระยะเวลาเก็บตามนโยบายขององค์กร
